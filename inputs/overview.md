# Amazon Developer Hackathon: Overview & Submission Details

## Theme: Build, Ship, Shape
Fire TV, Alexa+, Ring, and Bee are all part of one global hackathon. Build for one product or connect the living room, the front door, and the cloud.

## Primary Tracks
1. **Fire TV**
   - Launch demo-ready app on Fire OS or Vega OS.
   - Frameworks: React Native, Web technologies, Android (Kotlin/Java).
   - Priority categories: AI-enhanced viewing, sports, fitness, family entertainment, multi-modal UX, computer vision.
2. **Alexa+**
   - Self-hosted MCP server (spec 2025-11-25 or later, Streamable HTTP) or Agent Skill.
   - Or simulated Alexa+ experience in a web app using agentic tools.
3. **Bee (Wearable AI)**
   - Connects to real data recorded and processed through a Bee device or Apple Watch running Bee software, using Bee's CLI, MCP, or Agent Skills.
   - Live data interaction required.
   - Priority use cases: education, developer experience, personal productivity.
4. **Ring**
   - New app or extension using Ring APIs, SDKs, simulators, or devices (physical Ring device not required; simulator acceptable).
   - Priority categories: access control, business systems, IoT home automation, accessibility, caretaking.

## Mini Challenges (Stackable onto Primary Track)
- **AWS Builder:** Use AWS services (Bedrock, AgentCore, Strands SDK, Kiro Crew, SageMaker) with documented integrations.
- **Open Source:** New open-source project or public repo contribution (PR/fork/branch) during hackathon window.

## Submission Deliverables Checklist
- [ ] Text description of project (what it does, how it works).
- [ ] Public GitHub repository with open-source license visible in About section.
- [ ] Runtime code hooks for Alexa+/Bee/Ring (or Fire OS/Vega OS runnable build + video).
- [ ] Demo video under 3 minutes (public YouTube or Vimeo, English).
- [ ] Product feedback answers for EVERY tool/API/SDK used:
  1. Which tools/APIs/SDKs used and for what?
  2. What worked well?
  3. What needs work?
  4. Onboarding experience (zero to hello world)?
  5. Would you build with these devices/services again? Why?
  6. (If AWS Builder) Details on AWS services used and how.
- [ ] Open Source mini-challenge details (if participating): contribution URL, repo URL, GitHub username, description.
- [ ] Optional: Feature requests (with priority rating).
- [ ] Optional: Detailed Friction Log entries (up to **10% bonus** in judging!).
